# 赛富豪桌宠 · 技术说明

双击上一级 `run.bat` 启动桌宠，`run-review.bat` 打开本地情绪与工作陪伴预览。运行环境为上一级 `.venv`；完整仓库根目录提供 `setup.bat`。

额度条同时显示服务端返回的五小时、一周剩余百分比，例如 `5小时 86% │ 周 98%`；它不是剩余 token 数或月余额。每 180 秒同步一次。鼠标停在额度条上可看窗口重置时间、最后同步时间；拖动额度条可移动桌宠；右键宠物或托盘图标可刷新、预览、退出。

宠物身体不显示悬停提示；工作气泡支持专用任务浮层。额度详情提示和任务浮层使用独立的深底浅字样式，不受透明动画样式影响。

## 每日使用建议

左侧独立卡片显示今日还可用额度、已用 / 建议量。按北京时间每日 02:00 至次日 02:00 记录，头顶的五小时和周额度保持原样；右键“显示每日建议”可隐藏卡片并记住选择。

以服务端真实周重置时间定位本轮第几天：第一个用量日的建议为当时周剩余 / 7，第二天为新的周剩余 / 6，随后 / 5、/ 4、/ 3、/ 2、/ 1。若周重置时刻不在 02:00，最后不足一天仍按 1 天分配；周额度实际重置后重新计算。当天建议固定，不随每次同步缩小分母或重新分配；例如周剩余 84%，首日建议为 12 个周额度百分点。

以北京时间 02:00 附近的历史周额度为基准，减去后续读数估算今日消耗。启动和换日时扫描本地 Codex 日志中 `token_count` 携带的历史额度元数据，并合并桌宠自己持久化的额度快照；不会将安装时刻当作今天的起点。若本轮周额度在今天重置，优先寻找真实的零使用快照恢复这轮完整消耗。本日跨周重置时，保留并合计已记录的前后两段。已观测消耗不会因服务端向上校正而被抹去。达到建议量的 80%、100% 时分别发出一次系统通知；跨过两条提醒线只发出一条。达到建议不会阻止使用。每三分钟同步，在每日边界额外请求刷新。

记录与额度采样独立保存在 `daily_budget.json`，重启继续计数、不会重复提醒。02:00 前最近的快照只能提供采样估算；若只能找到 02:00 后的部分记录，显示“≥”已确认的最低消耗，并标明缺口，剩余量只作为上限。无历史基准且尚未确认任何消耗时显示“今日消耗待恢复”，不会将未知写成 0。百分比具有服务端采样精度，不能换算为固定 token 个数。没有有效的周重置时间时显示等待同步。

## 数据来源

使用已安装的官方 Codex 可执行程序，通过标准输入输出运行 `app-server --stdio`。完成 `initialize` / `initialized` 握手后仅调用 `account/rateLimits/read`，随后关闭本次启动的服务进程。不创建线程或发起模型对话，登录续期由 Codex 管理，没有读取或输出登录令牌的代码。

优先读取 `rateLimitsByLimitId.codex`，兼容旧的 `rateLimits`。空值不当作 0，读取失败保留上次读数；窗口到重置时间也不会自行假定额度恢复。`ordinaryUsageAllowed=false` 按服务端阻断处理，额外积分为 0 不会被误判为订阅额度耗尽。

接口文档：https://learn.chatgpt.com/docs/app-server （Authentication / Rate limits）。当前实现不换算 token 余额或月额度。公开版仅包含 Codex 功能；原有 Kimi 版本保留在私有备份。

## 形态、情绪和自然衔接

按各额度窗口中较低的剩余百分比切换，阈值为 80% / 20% / 3%。

| 剩余 | 形态 | 行为 |
|---|---|---|
| ≥80% | 赛富豪 | 保留原始待机，附带动态工作徽章；专属情绪暂未制作 |
| 20%～80% | 宝箱索财灵 | 随机待机小动作、单击开心、快速连点嫌弃、闲置小憩、抬盖专注 |
| 3%～20% | 徒步索财灵 | 随机小动作、开心、温和的抗议，坐下休息与工作陪伴 |
| <3%，或服务端阻断 | 宝箱休眠 | 长睡、点击醒来张望再睡；工作时醒来专注，结束后再次入睡 |

- 正常待机每 16～30 秒随机小动作，不连续选择同一段；排除攻击、奔跑及大幅转圈。
- 每次点击立即显示轻触反馈，并可打断当前互动。使用严格的滚动 1 秒窗口：窗口内至少三次点击立即触发嫌弃；额外连点继续反馈，但不会反复将嫌弃重置到第一帧，没有原先的 8 秒冷却限制。
- 无点击、无工作约 110～170 秒后进入小憩，休息 18～28 秒；宝箱完整入睡，徒步完整坐下。点击或开工会先走原始唤醒／起身动作。
- 原动作切换做 160ms 平滑过渡，过渡合成保留亮度；开心和嫌弃按 1.25 倍速播放，开合、起身和循环维持原速。
- 宝箱专注进入、循环、退出都使用同一段 `notice01` 的连续原始帧；入口末帧、循环首末帧、出口首帧是同一姿态。离开循环时从当前实际帧对应的出口位置继续，不再硬接姿态不同的 `battlewait01_loop`。
- 开工直接播放一次开盖进入专注，取消此前完整张望后又合盖、重新开盖的重复路径。导出前先实际播放并预热原动作，补齐开盖初段，避免停住数帧后突然跳到张开。
- 工作中单击使用独立的抬盖回应，徽章显示“收到”；从当前开合或循环的实际帧衔接，回应后直接继续专注，不先合箱切到普通开心。工作中的随机小动作同样保持开盖。三连点仍快速收势后播放独立嫌弃动作。
- 输入优先于当前动作。开合、入睡、起身途中点击时，从当前原姿态快速收势或反向退出后回应；打断淡入时保留实际屏幕上的混合帧，避免画面突然回跳。形态改变会取消旧动作及请求。
- 收工使用专用 `finish01`：宝箱抬盖舒展、徒步举手回应，与单击的 `glad01` 分开；宝箱这段舒展不再放进随机待机池。

## Codex 工作陪伴

每秒只读 `CODEX_HOME/thread_history_1.sqlite` 中的回合状态，使用会话占用锁验证活跃写入者。不修改 Codex 配置，不发起模型调用。

悬停右上角工作气泡可查看当前全部运行任务及其本轮 / 会话累计 token。任务名优先使用 `state_5.sqlite` 中的可见名称；只扫描相应日志的有限尾部，并且仅解析 `token_count` 事件的计数元数据。用本轮起点之前的累计计数作基线，得出本轮消耗；无法读取基线时显示暂不可用，不把会话总计冒充本轮用量。计数包含缓存输入，输出已包含推理输出，不重复相加；它们不是当前上下文占用，也不能直接等同于周额度扣减。通常在模型调用完成后更新，未结算的流式生成可能尚未计入。列表每秒刷新，同样数量的任务更替也会刷新；较多任务可滚动查看，离开浮层后自动收起。只监测本机运行任务。

开工时直接抬盖进入持续专注；徽章显示动态账本与笔尖，附少量微光。专注时每 9～16 秒插入一个保持开盖的温和小动作。全部已观察到的工作回合确认成功完成，才播放收工庆祝；中断或失败时安静收势，状态读取不明时恢复普通待机。低额度休眠形态收工后张望并入睡，不复用正常形态的高兴动作。

多会话同时工作时，全部结束后才收工。工作状态包含推理、工具调用和等待交互，不能细分为纯思考。此读取依赖当前 Windows 桌面版的本地存储结构，并非稳定公开 API；结构不兼容时回退到普通待机，不监测其他电脑或纯云端任务。

审片窗口可直接预览开心、嫌弃、小憩，勾选“模拟 Codex 工作中”，并分别模拟成功收工与中断。模拟仅影响审片窗口。

## 原始素材与再生成

本地动作来自原绑定模型的 30fps 渲染，使用官方 Viewer 截图 API 获取 384×384 透明帧；每个模型统一裁切画布后打包为无损 WebP。索财灵沿用原始绑定动作；赛富豪直接使用已渲染的朱紫透明动画。运行时不依赖在线模型或浏览器。

重新生成需要 PySide6、Pillow 和网络，在仓库根目录依次执行：

```powershell
python codex-pet/export_assets.py chest
python codex-pet/export_assets.py roaming
python codex-pet/prepare_focus_bridges.py
python codex-pet/pack_assets.py
```

`prepare_focus_bridges.py` 从同一段原始连续帧构建完全匹配的专注开合、循环和可打断过渡，并保留来源索引。打包时记录 WebP 实际编码帧到原始帧的对应关系，避免重复帧合并后定位错误。素材工具和来源署名随程序保留，原始渲染缓存不必上传。

## 赛富豪素材限定版

赛富豪只保留已核验的朱紫原生冲浪循环（512×512、80 帧、2666ms），使用正常速度，无裁切、整图扭曲或新骨架动作。开工、点击和收工都不重置身体动画的播放相位。

单击有即时光圈和短暂回应气泡；1 秒内三次点击显示“别戳啦”。工作时显示“专注”，悬停仍可查看任务和 token；工作中单击短暂显示“收到”，成功结束显示“收工”，中断或失败显示“稍歇”。这些反馈只作用于气泡，不宣称身体执行对应动作。

自制的挥手、嫌弃、专注姿态、庆祝、小憩和随机动作已停用；对应审片按钮禁用或改为“点击爆金币”“连点反馈”。试制源文件仅保存在开发目录 `model-source/gholdengo/retired-procedural`，运行版旧动作会备份后撤下。索财灵的原动作与状态机保留。

运行 `review.py --gholdengo --demo` 可看实际效果；`test_gholdengo.py` 验证素材哈希、真实解码、工作 / 点击 / 收工不打断循环、连点反馈、能力按钮和形态切换。再生成时在开发目录准备 `model-source/gholdengo/ready-made/scarlet-front.webp`，运行 `python codex-pet/pack_gholdengo.py`。来源与低分辨率候选取舍记录见 `gholdengo-sources.json`。

## 点击金币特效

赛富豪单击即时弹出 7 枚小金币；连续点击时每簇减为 4 枚，总数最多 42 枚，并限制微光数量。金币使用本地矢量绘制的 48 相位缓存，包含细齿边、双层压边、凹刻菱形和金属高光，按各自速度翻转和旋转，沿抛物线散开并柔和淡出。工作中同样生效，不重置原生身体动画。动画约 1 秒自然结束，结束后停止特效定时器，切换形态和退出时立即清理。

`qa_coin_effects.py` 验证实际 Qt 绘制、桌宠边角轨迹不裁金币、连点数量上限、自然结束和形态切换清理，并生成效果预览；`test_gholdengo.py` 同时检查特效可见期间原生动画实例不变。
